{% load i18n icons %} {% comment %} One "Your Performance" summary card for a REP_TARGET challenge (issue #85, manual self-report follow-up) -- the sibling of _summary_card.html, showing progress toward a single (target_weight, target_reps) goal instead of Classic's rep-max ladder. Rendered both inline, once per lift, inside detail.html's Summary tab grid, and standalone as the htmx response of manual_rep_target_view (challenges:manual-rep-target) -- the latter swaps outerHTML onto exactly this card's own #summary-card- wrapper, so the markup here must always be a single complete replacement for itself. Two faces share one card, reusing the exact flip-card mechanism and JS (initManualLiftCard in detail.html) that Classic's card uses: the front is the read-only progress summary, the back is the self-report carousel. Unlike Classic (the lifter picks WHICH rep-max rung to confirm, and weight varies per rung), Rep Target's weight is a single fixed gate -- the goal's own target_weight -- so the carousel is reps-first instead: the lifter picks HOW MANY REPS they did, and each stop shows what that scores. Stops are only the reps counts that earn a new, distinct point value, so the carousel has min(target_reps, 10) stops, not always 10 (challenges.services._manual_targets_for_rep_target) -- the dots below follow that same count. data-mode="rep_target" is the only thing that tells the shared JS to word the label as "N pt target" instead of Classic's "NRM target"; every other field name and behaviour (paging, height sync, disabled-when-no-gain, confirm) is identical. can_self_report gates the whole self-report half of the card: when false (a COMPLETED/CANCELLED challenge -- see challenge_detail_view) the back face, the flip affordance, the flip-card CSS classes and the data-* attributes that wire the JS are all omitted, leaving a plain static summary. The classes have to go with it, not just the button: .flip-card-front is absolutely positioned and .flip-card gets overflow:hidden, so a card whose JS never runs to size .flip-card-inner would collapse to zero height and render blank.
