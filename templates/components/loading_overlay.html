{% load i18n %} {% comment %} Global loading overlay (TASK-141). Hidden until window.ppLoading.show(msg) is called; window.ppLoading.hide() dismisses it. Driven from two places: - HTMX requests, via the htmx:beforeRequest/afterRequest wiring in base.html (fires for any element carrying data-loading-message). - Plain (non-HTMX) PRG interactions, via the delegated submit/click listeners below — needed because htmx events never fire for plain
POSTs or navigations (e.g. goal setup, challenge-detail links). A pageshow listener force-hides on bfcache restore so the Back button never leaves a stuck overlay after a full-page navigation. setProgress(fraction) drives an optional byte-upload progress bar (base.html's htmx:xhr:progress wiring, real upload bytes via htmx's XHR event passthrough -- lengthComputable-gated there, not fabricated). It's only ever a fraction of the truth for something like a file import: it tracks bytes reaching the server, not the server then parsing/scoring them, which has no client-visible signal at all. show()'s optional processingMessage is what covers that gap -- base.html swaps to it once the upload itself finishes (htmx:xhr:loadend) but the response hasn't arrived yet, so the message doesn't keep implying "upload" progress for a phase that isn't upload anymore. {% endcomment %}
